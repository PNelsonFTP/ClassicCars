## ClassicCars adapter implementation evidence

- Standard search form: POST `https://classiccars.com/listings/find` with observed controls `YearFrom=1960`, `YearTo=1989`, `Make=Ford` / `Chevrolet`, `Model=Mustang` / `Camaro` / `Corvette`, `Country=United States`, `Zip=60187`, `Distance=500`, all three seller categories selected, `PageSize=60`, `SortTerm=datelisted`, `SortAscending=false`.
- Redirected GET example: `https://classiccars.com/listings/find/1960-1989/ford/mustang?country=united-states&distance=500&ps=60&s=datelisted&zip=60187`. The form's supported radius options are 25, 50, 100, 250, 500 miles. The 500-mile discovery option was selected to avoid accidental undercollection; it is not a routing promise or a guaranteed exact geodesic radius.
- Cards use `.search-result-item`; ad anchors have stable `/listings/view/{numericId}/{slug}`. Card structured data has `sku=CC-{numericId}` and offer URL, which were checked against that exact card ID. No positional joins.
- `link[rel=next]` supplies supported page progression. First-page ►► jumps only to page 6 even when total pages are 8/7/10; it must not be mistaken for the final page. Last pages contained 7/19/41 cards respectively and no next link. All 1,387 IDs were distinct across 25 pages.
- Cards contain usable factual metadata and a photo from that exact ad, but structured `availability="n/a"` is **unknown**, not active. Detail `h1` identifies ordinary "For Sale:" versus "For Sale at Auction:"; auction phase remains unknown absent dated evidence.
- Detail JSON-LD is demonstrably unreliable: literal unescaped newlines make some JSON invalid, image can equal a .NET collection type name, currency can say `USC`. Source-specific DOM uses `.vehicle-details li` and **direct child spans** for label/value. This prevents financing-payment text or third-party advertisements from replacing asking price. `$21,500 (OBO)` is asking price 21500 plus negotiable, not missing.
- Detail `meta[property="og:image"]` gives an actual same-ad full image URL. Gallery `meta[itemprop=image]` is ad-specific; retain remote URLs, do not substitute unrelated model photography.
- `#seller-information [aria-label="Seller or Company Name"]` yields seller identity; dealer listing links identify dealer type. Actual vehicle and seller location remain separate.
- **Off-site test:** [CC-2105001](https://classiccars.com/listings/view/2105001/1982-chevrolet-corvette-for-sale-in-cadillac-michigan-49601) advertises Cadillac, Michigan but explicitly says the vehicle is at the client's home and not in Cadillac. Actual location is unresolved. Its structured VIN `000000000AAH34109` is a placeholder and must not auto-group; a different identifier occurs in seller prose.
- **Auction test:** [CC-2103447](https://classiccars.com/listings/view/2103447/1966-ford-mustang-for-sale-in-corydon-indiana-47112) is a Beckort 1966 Mustang auction with no fixed ask; current bid/end/timezone not established. Exclude from the everyday fixed-price view.
- **Tribute test:** CC-2103387 explicitly claims an L88 tribute. Do not upgrade to a factory L88.
- Advertised odometer `0` is preserved with an unknown-mileage caveat. Seller claims are not independently verified. Identifiers of different historical lengths are retained without a modern-17-character validation requirement.
- All fetched HTML observations have original network timestamps in `detail-results.json` or `regional-results.json`; parsing/re-reading them does not refresh those timestamps. Seller posted time was not established. This pass does not create retrospective price history.

## Deliverables and import guidance

`normalized-inventory.json` contains 1,387 real records, including catalog-only records flagged pending detail enrichment. `collection-summary.json` records per-page counts, identity sets and observation times. `detail-results.json` and `regional-results.json` audit every successful ClassicCars collection request. `robots-results.json`, `terms-results.json`, `homepage-results.json`, and additional catalog result files record research outcomes. Raw files should stay private and ignored by Git.

For a conservative first public display, `detail-inventory.json` contains only the 31 enriched ads. Using those 31 as the displayed subset must still show the collected 1,387 and pending 1,356 in coverage rather than silently discarding the discovery pool. No routes were fetched, so known four-hour matches are zero and travel-unresolved count equals every displayed candidate. None is asserted to meet the four-hour limit. A complete catalog enumeration for one query does not prove a complete regional market.

Nationwide expansion has not been collected in this regional pass. Removing the source ZIP/distance parameters and following a new full pagination run is needed; merely removing frontend geography does not create nationwide coverage. Geographic filtering must still exclude unknown actual locations and non-US stock. Specialty expansion was not collected here and must be a separate query branch; no 1990+ ordinary Mustang or late Camaro/Corvette should enter it.

## Autotrader validated implementation details

The final bounded probe verified the main Autotrader source, separate from Classics on Autotrader. `autotrader-inventory.json` has 19 source-observed Mustang listings and one detail-enriched record, AT 746083047, advertised in Naperville by Power Motorcars Inc. Its asking price is $19,800; the source also carries a past `priceValidUntil` date, retained as a price-reconfirmation flag. No historic prices or seller posting dates were inferred from `daysOnSite`.

Use `__NEXT_DATA__.props.pageProps.__eggsState.srp_results.activeResults` to choose matching IDs, then join to `inventory[id]` and `owners[ownerId]`. The embedded inventory includes additional sponsored ads which are outside the year scope; selecting every embedded inventory record is wrong. Owner city/state are under `location.address`; dealer coordinates are not a geocoded actual stock location. Preserve `isVirtualDealer` and `isMarketExtListing` as unresolved-location reasons. Match detail IDs via `vdp_results.activeResults` and the keyed inventory. The live query reported 19 matches, all 1987–1989; this source did not prove coverage of every 1960–1986 car.

`source-parsers.mjs` supplies tested JavaScript parser functions for both sources, using Cheerio, with no network side effects. `fixtures/` contains minimized/sanitized source fixtures for pagination, off-site location, OBO price, auction semantics, and sponsored-inventory identity selection. `PARSER_VALIDATION.json` records checks actually passed. The validation helper uses the current project dependency path only for this research session; the reusable parser module has a normal `cheerio` import.

`all-inventory.json` combines 1,387 ClassicCars plus 19 Autotrader ad records = **1,406 raw ads**, without claiming a grouped physical-vehicle count. `all-detail-inventory.json` is the 32 detail-observed subset (31 ClassicCars + 1 Autotrader). One detail is an auction of unresolved phase; no auction current bid was guessed. Every route remains unknown. Do not relabel 1,374 pending detail records as enriched or known active.
